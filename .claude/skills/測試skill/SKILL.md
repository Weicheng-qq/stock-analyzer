# 測試skill — 股票 App 真實使用者測試

## 這個 Skill 的核心立場

**不要只做 Code Review。一定要實際操作 App。**

這是投資分析 App，一個錯誤的數字可能讓使用者做出錯誤的投資決策。所以：

- 目標不是「確認程式可以跑」，而是「**找出任何可能讓真實使用者看到錯誤、過時、不完整、矛盾或誤導資訊的地方**」。
- 「程式技術上沒錯，但使用者很容易誤會」也算 Bug，要列出來。
- **寧可找出 20 個 Bug，也不要漏掉 1 個可能影響投資判斷的重大 Bug。**
- **絕對不可以假裝測試過。** 如果環境無法實際操作瀏覽器，必須明講「目前無法進行真實瀏覽器操作」，不要用讀程式碼的結論冒充實測結果。

---

## 執行順序（不可跳步）

```
0 環境探測 → 1 讀已知踩坑 → 2 實測找 Bug（先不要修）
  → 3 列 Bug 清單並分級 → 4 修 P0/P1 → 5 回歸測試 → 6 交付報告 → 7 更新文件
```

**第 2 步結束前不要動任何程式碼。** 邊測邊修會讓你只看得到自己剛改的地方，漏掉整體性的矛盾。

---

## 步驟 0：環境探測（先做，決定後面怎麼測）

### 0-1 瀏覽器工具能不能用
先 `preview_start`，再試一次 `computer` 的 `left_click` 或 `screenshot`。

- **正常** → 用真正的點擊操作，最貼近真實使用者。
- **`computer` 逾時並回報「Browser pane is currently hidden」** → 這個 session 的面板是隱藏的，指標層級的點擊做不到。**改用 `javascript_tool` 呼叫 App 真正的事件處理函式**（`runSearchBar()`／`pickGroup()`／`el.click()`）——走的是真實流程與真實網路請求，只是不是指標點擊。**必須在報告中揭露這個限制**，並說明純觸控／滑動類問題無法驗證。
- **完全沒有瀏覽器工具** → 直接告訴使用者「目前無法進行真實瀏覽器操作」，不要繼續假裝。

### 0-2 該在哪裡測（這一條很重要，搞錯會白測）

| 測什麼 | 在哪裡測 | 原因 |
|---|---|---|
| 搜尋、財報、新聞、即時報價、AI 分析 | **正式站** https://weicheng-stock.vercel.app | 本機預覽是 `python -m http.server` 純靜態，**沒有 `/api/proxy` 後端**，這些一定失敗（交接記錄已列為「非缺陷」） |
| 今日市場、IR 內容、AI 快取等靜態 JSON | 本機 `preview_start` + `stock_analyzer.html` | 讀 `data/**` 靜態檔，本機就測得到，改一行就能立刻驗 |

⚠️ **正式站跑的是 `index.html`（已部署版），本機改的是 `stock_analyzer.html`。** 還沒 push 的修改在正式站看不到 —— 想在正式站驗新程式，就得先部署（見步驟 5）。

### 0-3 手機優先
一律 `resize_window width:390 height:844`。使用者的硬性鐵則是「這個 App 主要是手機 App」，桌機寬度的判斷不算數。測完記得 `preset:"desktop"` 還原。

### 0-4 模擬第一次使用的人
```js
localStorage.clear(); sessionStorage.clear(); location.reload();
```
⚠️ **切換市場（`setMarket`）本質是 `location.reload()`**，程式化連續呼叫會被重載打斷。**一定要分兩步**：先 `localStorage.setItem('market','tw')` → `location.reload()` → 等 2 秒 → 再操作。

| 輪次 | 這個人會做什麼 |

| B | 美股 → 搜尋 NVDA → 財報 → 法說會 → 返回 → 再進去 |

| D | 沒有自選股 → 看今日市場 → 加入股票 → 移除股票 |
| E | 故意亂輸入：不存在代碼、空白、只有空白、特殊符號、中文名、英文名 |
| F | API 慢／失敗／回空資料／某項資料缺失（用 `window.fetch` 覆寫模擬） |
| G | 看即時行情 → 財報 → 法說會 → 回首頁，**確認同一支股票在不同頁面數字一致** |

## 步驟 3：列 Bug 清單並分級

| 等級 | 定義 |
|---|---|
| 🔴 P0 | 使用者會看到**錯誤的數字／錯誤的公司資料**，或嚴重安全問題 |
| 🟠 P1 | 嚴重誤導使用者，或重要功能無法使用 |
| 🟡 P2 | 一般功能 Bug、顯示錯誤、誤導性文案 |
| 🟢 P3 | 小型 UI／文字／排版問題 |

**每個 Bug 必須寫齊**：編號／嚴重程度／【問題】／【重現步驟】／【實際結果】／【預期結果】／【可能原因】／【風險：是否可能造成錯誤投資判斷】／【修正建議】。

## 步驟 4：修正（只修 P0／P1，P2 視成本順手修）

- 修改前確認**根因**，不要只修一間公司 —— 使用者的鐵則第 5 條：「**發現錯誤不要只修一間公司，所有公司可能都有一樣的問題**」。
- 每個修正處都要留繁體中文註解，**寫清楚「實測看到什麼」**（例如「實測台積電 2025/08 顯示 +869.4%」），下一個接手的人才知道為什麼不能改回去。
- 不可破壞既有功能：優先「新增」而非「修改」，比照 `themeCard`／`etfCard`／`dailyCard` 的既有模式。

---

## 步驟 5：回歸測試（修完不可以直接說完成）

1. **語法檢查**（必做）：
   ```bash
   python -c "import re,io; s=io.open('stock_analyzer.html',encoding='utf-8').read(); b=max(re.findall(r'<script[^>]*>(.*?)</script>', s, re.S),key=len); io.open('_c.js','w',encoding='utf-8').write(b)"
   node --check _c.js && rm -f _c.js
   node --check scripts/<改過的檔>.mjs
   ```
2. **本機驗靜態部分** → 通過後才部署。
3. **部署**：`cp stock_analyzer.html index.html` → `diff -q` 確認一致 → commit → `git fetch` → 有落後就 `git pull --rebase` → `git push`（Vercel 約 1 分鐘）。
   > 遠端常有 `AI快取：xxx` 的自動 commit（測試時搜尋公司會觸發網站自己寫入），rebase 即可，不是衝突。
4. **正式站重跑一次完整 golden path**：冷啟動 → 台股 → 美股 → 搜尋 → 個股頁 → 財報 → 法說會 → 新聞 → 今日市場 → 自選股 → AI 分析 → 錯誤搜尋 → 快速點擊 → 手機 390px 截圖。
5. 確認**先前發現的每一個 Bug 都真的不見了**，且**沒有製造新的**。

## ⚠️ 測試時自己不要犯的錯（實戰教訓）

1. **用假資料驗版面後一定要還原。** 流程：`git status --porcelain` 確認乾淨 → 改 → 驗 → `git checkout data/` → **再 `git status` 確認真的還原了**。（本專案曾發生「被 DRY RUN 測試資料覆蓋每日資料」而需要專門 commit 還原。）
2. **呼叫內部函式前先看簽名。** 例：`doSearchTW()` 要的是 `'2330.TW'` 不是 `'2330'`，傳錯會得到「查不到此台股資料」而誤判成 App 的 Bug。使用者真正的入口是 `runSearchBar()`。
3. **`alert()` 會卡住自動化。** 測錯誤輸入前先 `const oa=window.alert; window.alert=m=>logs.push(m);`，測完還原。
4. **測試會污染 localStorage。** 若在正式站改過 `watchlist` 等鍵，測完要 `removeItem` 還原成預設。
5. **不要把「資料源限制」當成程式 Bug。** 例如本機沒有 `/api/proxy`、SEC 對某些外國發行人只有年報 —— 這些交接記錄已列為「非缺陷」。
6. **懷疑之前先查證。** 例如 AI 快取鍵 `gem_AMD_2026Hbuk8q8` 看起來像亂碼，實際是 `__quarterTag()` 對非制式季度字串的雜湊備援，是**預期行為**。下結論前先讀那段程式。

## 🎯 已知的高風險模式（每次測試都要專門檢查這幾類）

這些是實戰中真的發生過的錯誤類型，**同類問題極可能出現在別的地方**：

1. **雙掛牌陷阱**：`window.__symbolForLinks` 對台股是刻意指向美股的（2330→TSM）。**IR 官方事實可以兩市場共用，但凡是「由股價推導」的東西（技術面／市場情緒／估值／本益比／每日評分）一律不可共用。** 檢查任何新功能有沒有誤用它。
2. **期間對齊**：累計／YoY／QoQ 的分子與分母期間必須一致。資料視窗不足時**要顯示「—」而不是硬算**。（月營收累計YoY 曾顯示 +869.4%。）
3. **「今日」標籤**：週末與休市日不可以寫「今日」，那是上一個交易日的數字。看有沒有 `tradeDate` 可以據實標示。
4. **市場混淆**：台股模式不該出現整排美股內容，反之亦然。個股類資料依市場過濾，總體類（美國經濟數據）兩邊都留。
5. **新聞相關性**：外部新聞 API 會夾帶同類股但無關的公司。必須用 `relatedTickers`（美股）或公司中文名出現在標題（台股）過濾，**但過濾到一則不剩時要退回原清單**。
6. **外部 JSON 型別**：一律 `Array.isArray()` 防護，否則 `.filter is not a function` 會讓整頁渲染中斷。
7. **`null` 被當成 0**：JS 裡 `null>=0` 是 `true`，會印出憑空的「▲0.00%」。缺漏值要顯示「—」。
8. **錯誤訊息要分辨**「這個東西不存在」與「暫時失敗，請稍後再試」，後者會讓使用者一直重試。
9. **AI 用語**：不可寫成買賣建議、不可把推測寫成事實、不可因為股價漲就說「因為利多」（循環論證）。**沒有資料就寫「目前沒有明確消息」。**
10. **AI 評分與結論矛盾**：例如評分 80/100 卻寫「短期風險偏高」，或同一頁兩張卡片給出相反的技術面判斷。
11. **快取新舊**：切頁面／切市場／重新整理後，會不會顯示上一支股票的資料或把昨天當今天。
12. **XSS**：所有外部字串（新聞標題、AI 輸出）進 `innerHTML` 前必須經過 `esc()`。
