## 1. 網站架構（技術）

### 1.1 檔案結構
- **`stock_analyzer.html`** — 本機開發版（單一 HTML 檔，內含全部 HTML/CSS/JS，無框架、無 build）。
- **`index.html`** — 線上部署版。
- **鐵則：兩檔內容必須完全一致。** 每次改完 `stock_analyzer.html` 一定要執行：
  ```bash
  cp stock_analyzer.html index.html
  ```
  再一起 commit。（可用 `diff -q stock_analyzer.html index.html` 驗證。）
- **`CLAUDE.md`**（專案根目錄）— 本專案專屬提醒，Claude Code 自動載入。
- **`專案交接文件.md`**（專案根目錄）— 更早期的技術踩坑與函式位置紀錄。
- **`交接清單/`**（本資料夾）— 這份文件 + 股票APP Skill + Excel 精神紀錄。

### 1.2 部署流程
- 部署平台：**Vercel（免費方案）**，綁定 GitHub repo。
- 流程：`git push origin main` → Vercel 自動偵測並部署，**約 1 分鐘**上線。
- 沒有伺服器、沒有資料庫，是純靜態單頁應用（SPA）。

### 1.3 資料來源與代理
- **財務數字**：SEC EDGAR（`data.sec.gov/submissions/CIK{10碼}.json`）＋ Yahoo Finance。
- **AI 分析**：使用**免費**的 AI 模型（遵守零費用鐵則）。
- **CORS 代理**：`/api/proxy`（Vercel serverless function）用來抓 SEC 全文、繞過瀏覽器 CORS。
- **10 年財務**：`isAnnualForm` 接受 10-K / 20-F / 40-F / 6-K；`extractAnnual` 用「財年結束月份」比對；`pickUnit(units, instant)` 挑年度資料最多的幣別。

### 1.4 前端渲染關鍵函式
- `renderAI()` — 把 AI 分析結果與 IR 常數渲染到頁面。
- `#ai_guidance` — 渲染「法說會 CEO 前景展望」，資料來自 `IR_CALL_SUMMARY`。
- `#ai_products` — 渲染「產品與服務」，資料來自 `IR_PRODUCTS_SUMMARY`。
- **注意：IR 內容在 AI 分析完成後才會渲染出來**（不是一載入就顯示）。

### 1.5 Service Worker（重要踩坑）
- 曾因 Service Worker 造成**重新整理無限迴圈**（我自己寫的 kill-switch `c.navigate(c.url)` 造成迴圈）。
- **現狀**：SW 已被改成「純 kill-switch」——只做 `unregister` + 清 caches，**不做 navigate、不 claim**；HTML 已**不再註冊** SW。不要再把 SW 加回來。

## 2. 三大核心鐵則（最重要，違反等於做錯）

### 鐵則一：以事實為依據，絕不 AI 臆測
- 數字**只能**來自官方來源（SEC EDGAR / Yahoo / 公司官網 IR）。
- **絕不可**用 AI 編造、用常識或訓練記憶臆測，**不做預測性斷言**。
- 定性欄位（產品／競爭對手／護城河等）**禁止**回「無公開資料」——要用官方年報＋維基組出實際內容；**只有真正查無的「數字」才可留白**。
- 遇到「AI 好像漏抓某事實」→ 先查**官方文件全文**（用 `/api/proxy` 抓 SEC 全文），**不要**放寬 prompt 讓 AI 用常識硬補。

### 鐵則二：法說會與產品，一律「公司官網 IR 優先」
- 每間公司的「法說會 CEO 前景展望」都要**先從該公司官網「投資人關係(IR)」**找：法人說明會逐字稿、簡報、財務報表、營運績效報告、線上會議影片，擷取重點（**特別是最新成長展望＋資本支出**）。
- **官網找不到，才退回 SEC 官方新聞稿。**
- **產品**也一樣：從公司官網抓最新一季的產品／營收結構（比年報新）。
- 使用者原話：**「所有搜尋的公司，產品和法說會請從公司網址去抓最新的資訊」**、**「與台積電邏輯一樣」**。

### 鐵則三：修正後一定自我驗證
- 完成任何修正／實作後，**必須自己先驗證**（跑測試、實際操作網站、檢查輸出、語法檢查）。
- **不可以讓使用者自己測試時才發現問題。** 前端變更要在瀏覽器實際操作 golden path 與邊界情況再回報完成。

## 3. 法說會／產品「官網 IR 優先」的實作細節

### 3.1 三個常數（都以股票代碼 keyed，人工判讀寫死）
| 常數 | 內容 | 渲染位置 |
|---|---|---|
| `IR_CALL_SUMMARY` | 法說會前景展望（最新一季） | `#ai_guidance` |
| `IR_PRODUCTS_SUMMARY` | 產品／營收結構（最新一季） | `#ai_products` |
| `IR_QUARTERLY_PAGE` | 公司官網 IR 法說會頁連結 | 來源連結 |

- 每筆物件格式：`{ quarter, source, html: \`...\` }`。
- 這三個常數的內容**優先於**原本的 SEC／AI 邏輯。
- **競爭對手**因法說材料不涵蓋，維持年報來源（不進這三個常數）。

### 3.2 抓取技巧（官網常擋 curl）
1. 官網常有 **Cloudflare / Akamai** 擋 curl。
2. 用**內建瀏覽器**（`mcp__Claude_Browser__`）登入該網域取得 session cookie，`read_page` 拿檔案連結。
3. 再用「**瀏覽器 cookie + 桌面 UA**」curl 下載 PDF。
4. 逐字稿 PDF 用 `pdftotext -enc UTF-8` 解析（poppler 已裝，Python 無 PDF 套件）。
5. 簡報 JPG 可直接用 Read 判讀，且常同步申報在 SEC。
6. **官網 CDN**（q4cdn / cloudfront）多可直接 curl（例：GOOGL=abc.xyz、META、AMZN）。
7. **SEC 備援**：SEC 8-K 的 EX-99.1（外國公司為 6-K）就是公司自己申報的**同一份**官方新聞稿。EDGAR 抓法：`data.sec.gov/submissions/CIK{10碼}.json` → 找 item 2.02 的 8-K（或 6-K）→ 用 `index.json` 列出檔案 → 抓 exhibit（檔名多含 `99` 或 `earningsrelease`）。

### 3.3 金額換算規則
- 美元 billion → **億**（1B = 10 億）。
- 保留原幣別：韓元用「兆韓元」、歐元用「億歐元」、英鎊／美元照標。
- **絕不做 AI 幣別換算**（只照官方原文換算單位）。

### 3.4 已知擋 curl 的公司（退回 SEC 同一份文件）
- **TSLA / LLY（禮來）** 用 Akamai bot manager，TLS 指紋擋 curl，**即使帶 cookie 也 403/000** → 退回 SEC 同一份 8-K EX-99.1。
- 其餘官網擋 curl 者，一律退回 SEC 同一份官方文件。
- **使用者明確要求**：能從官網抓就從官網抓，不要走 SEC 捷徑（雖 EX-99.1 是同一份，但官網常有更完整的簡報／逐字稿）。

### 3.5 新增一間公司的標準流程
1. 內建瀏覽器開該公司官網投資人關係頁、取 cookie ＋桌面 UA。
2. curl 下載最新一季「投資人簡報／逐字稿 PDF」。
3. `pdftotext -enc UTF-8` 解析。
4. 逐項核對後寫進 `IR_CALL_SUMMARY` ＋ `IR_PRODUCTS_SUMMARY` ＋ `IR_QUARTERLY_PAGE`（數字全照官方原文、金額換算億／兆、標幣別）。
5. **驗證**：`grep -c "'SYM': {"` 應等於 **2**（call + products 各一）；用 Node.js `new Function` 編譯三個常數確認無語法錯誤；`cp` 同步後 `diff -q`。

### 3.6 兩個物件 anchor 容易搞混（踩過的坑）
- 新增／更新時：**先寫 `IR_CALL_SUMMARY` 的區塊、再寫 `IR_PRODUCTS_SUMMARY`**。
- 兩個物件的 anchor（同一句話）容易搞混——曾把 call 內容誤植到 products。
- 解法：**用「前一檔的獨特句子」當 anchor** 來區分要插入的位置；寫完 `grep -c` 確認 = 2。

## 8. 環境與踩坑速查（Windows / Bash / Python）

- 主要工作目錄：`C:\Users\Amber Lin\weicheng claude\股票`。
- Shell：PowerShell（主）＋ Bash（POSIX）。Python 讀檔用 **Windows 路徑（`C:/...`）非 `/c/...`**。
- Python 輸出中文：用 `PYTHONIOENCODING=utf-8` ＋ `sys.stdout.buffer.write(...encode())`，避免 cp950 UnicodeEncodeError。
- 避免在 inline python-in-bash 用會被 shell 吃掉的字元；**多行內容改寫成 `.py` 檔**再執行（曾出現 `[d.]+: command not found`）。
- SEC 抓取一定帶合規 UA（含 email），例：
  `Mozilla/5.0 (...) AppleWebKit/537.36 stock-research aa910517@gmail.com`。
- 抓 exhibit 用該筆 filing 的 `index.json` 列檔最穩（檔名不一定含 `99`，也可能是 `...earningsrelease.htm`）。
- 語法驗證：用 Node.js `new Function(objSrc)` 編譯三個常數；template literal 內小心 `` ` `` 與 `${`（我寫的內容都避開）。
